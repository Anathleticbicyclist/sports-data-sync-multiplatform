## 5. 自查阶段修复的四处缺陷（本轮）

> 下列缺陷均由发布方在真机日志或反解包体中发现、本机修复后重编；不修则 `detectStrava` 链路整体失效或进程自杀。

**(1) `UploadResult` 构造位次错一位（`UploadEngine.uploadToStravaWeb`）** — 原 `new-instance v3` 后紧跟 `const/4 v3, 0x1/0x0`，把 `this` 覆盖成整数，运行时 `VerifyError: [0x3E] tried to get class from non-reference register v3 (type=Precise Constant: 1)`，整个 `UploadEngine` 类被校验器拒绝。改为 `new-instance v3` + `const/4 v4, <bool>` + `const-string v5` + `v6..v10` + `invoke-direct/range {v3 .. v10}`。

**(2) `detectStrava` CAS 极性反了** — `compareAndSet` 后原写 `if-nez v3, :ds_ret`（抢到锁反而 return，锁留 true），改为 `if-eqz v3, :ds_ret`（抢不到锁才 return）。不修则每 1 秒发一次网络请求、可能并发堆积。

**(3) `detectStrava` cookie 空值兜底标签位置错** — 原 `if-nez v1, :ds_c1_empty` / `goto :ds_c1_done` / `:ds_c1_empty` / `const-string v1, ""`；`if-nez` 是"非零则跳"，真 cookie 被跳到赋空串段抹成 `""`，`length()` 恒 0、检测永不触发。按 Kotlin `?: ""` 原生形态改为 `if-nez v1, :ds_c1_done` + `const-string v1, ""` + 标签在赋值之后（v2 同理）。

**(4) `isStravaWebLoggedIn` 缺 `xor-int/2addr` 翻转** — 原方法真值是反的（`null`/空串 → true、非空 → false），接通 `isLoggedIn` 前置块后，**没有 cookie 的机器也会显示 Strava 已登录**（登录页假阳性 1/20）。已补一条 `xor-int/2addr v0, v1`，位置在 `:goto_1` 之后、`return v0` 之前，与 Keep/Outbase/Blackbird/Magene/Zwift 等 22 个兄弟方法一致。**归属说明：该方法是我方照参考实现手写新增（官方 9.6.6 的 `PrefsManager` 里 Strava 相关 0 行，方法数 280 → 现 288），漏翻属我方实现缺陷，不是原包缺陷。**

**(5) 合成 lambda 访问级别（`detectStrava$lambda$47/48`）** — 原声明 `.method private static final`，但 `LoginWebActivity$$ExternalSyntheticLambda47/48.smali` 用 `invoke-static` **跨类调用**，运行时抛
`IllegalAccessError: Method 'void com.jichi.ob.ui.LoginWebActivity.detectStrava$lambda$47(String, LoginWebActivity)' is inaccessible to class 'com.jichi.ob.ui.LoginWebActivity$$ExternalSyntheticLambda47'`，
检测线程死亡 → App 自定义 UnhandledExceptionHandler 记「检测到上次崩溃」并杀进程 → 用户看到"还没机会输账号，页面自己关了"。改为 `.method public static final`（Kotlin 原生合成 lambda 即 `public static final synthetic`），方法体一行未改。
**覆盖漏洞定性：此前三轮冷启崩溃计数全 0，是因为没有人点「登录Strava」，该路径从未被执行；冷启门禁不能替代登录页实测。**


**(6) `StravaApi` 四个方法寄存器/类型错，类被校验器整体拒绝（`VerifyError`）** — 真机日志（`work\fix967\logcat_lampub_fakecookie_web.txt` 142–150 行）：
`FATAL EXCEPTION: Thread-8` / `java.lang.VerifyError: Verifier rejected class com.jichi.ob.api.StravaApi`，四个方法各自报错：
`<init>(Context)` `[0x18]` wide register v1 同时被当作 Constant 30 与 TimeUnit；`fetchCsrf()` `[0x6B]` v5 被当作 Integer 但期望 String；`pollProgress(String)` `[0x6E]` expected 2 argument registers / signature has 1; `uploadFit([B,String)` `[0x3D]` v6 被当作 MediaType 但期望 byte[]。
**根因**：`<init>` 写 `.locals 3` 时 `const-wide/16 v1, 0x1e` 已占用 v1/v2 宽对，紧接着 `sget-object v2, TimeUnit->SECONDS` 把 TimeUnit 写进宽寄存器高半，`invoke {v0,v1,v2}` 三个寄存器装不下 `(J, TimeUnit)` 四个槽；`fetchCsrf` 用 `move-result v5` 把字符串槽 v5 写成 int 后再当 String 传参；`pollProgress` 与 `uploadFit` 的实参寄存器与签名位次整体错位。
**改法（仅寄存器编号与 `.locals`，控制流未动）**：`<init>` 改 `.locals 4` + `sget-object v3` + `invoke-virtual {v0, v1, v2, v3}`；`fetchCsrf` 的两处 `indexOf` 结果改落 `v6`/`v8`，`substring(II)` 用 `{v2, v7, v8}`；`uploadFit` 的 `RequestBody.Companion->create$default` 用 `invoke-static/range {v5 .. v11}`（receiver v5 / `[B` v6 / `MediaType` v7 / 三个 int / Object）；`pollProgress` 对齐实参槽位。
**验证**：反解包内同一类逐条比对，`invoke-*` 寄存器数与签名槽数比对 **0 处不一致**；四方法形态与树一致。
**归属**：`StravaApi` 是 9.6.7 新增的脚手架类（9.6.6 无此类），属我方实现缺陷，非官方遗留。
**为什么前三轮门禁没抓到**：无 cookie 时 `detectStrava` 在 `length() < 20` 处直接 return，`new StravaApi()` 从不执行，类也不会被校验器加载；只有 cookie 非空才会触发。**冷启与无 cookie 登录页门禁都不覆盖这条路径。**

## 7. 本轮（fix3 → fix8）追加修正：Strava 网页登录闭环与「已登录」判定

> 第 5 节修的是「能不能跑起来」；本节修的是「跑起来之后状态对不对」。两者都只落在 `MainActivity` / `MainActivity$loginLauncher$1$3` / `PrefsManager` / `UploadEngine` 四个文件。

**(1) 网页登录回传被送进 OAuth 兑换（fix3）** — 网页登录成功回调里 `login_type="strava"` 被当作 OAuth 平台处理，进入 `DevOAuth2Api.exchangeCode`，失败即打「token 换取失败」。改法：`loginLauncher$lambda$1` 的 `:cond_38` 前插硬闸门 `fix3StravaCookieOnly(type, session)` —— `type` 以 `strava` 开头且 data 含 `=` 时只调 `saveStravaWebCookie` 并返回 true；`MainActivity$loginLauncher$1$3` 再加二次兜底 `return-void`，任何路径都不会再构造兑换协程。

**(2) cookie 未落库（fix5）** — `saveStravaWebCookie` 往 `SharedPreferences`（key `strava_cookie`，prefs 名 `jichi_ob`）写入，成功后打印「✅ Strava 网页登录成功，已保存 N 字节 cookie」；真机实测 2438 / 2474 / 2428 B 三种长度均写入成功。

**(3) 上传侧凭证语义错位（fix6 / fix7）** — 参考实现里「凭证即 cookie」，直接把它当字符串参数传给上传；本包 `uploadToStravaWeb` 却把 credential 当标题、又自己去读 prefs。改法：
- `PrefsManager` 新增 `public static fix3StravaCookie:Ljava/lang/String;`，`saveStravaCookie` 首行 `sput-object` 同步内存副本，`logoutStravaWeb` 追加清空；
- `getCredential(DataSource)` 顶部加 STRAVA 前置分支（返回 `getStravaCookie()`）；
- `uploadToStravaWeb` 改「凭证优先、空则读 prefs、仍空才报未登录」，标题固定常量「鸡翅幸哲迈进OB」。

**(4) 判定极性写反，非空 cookie 被判成未登录（fix8，根因）** — `getStravaCookie` 与 `isStravaWebLoggedIn` 的长度判定误用 `if-nez`（Dalvik 语义是"不为 0 才跳"），等价于「非空 → false」，`uploadToStravaWeb` 的 `length()` 与 `isBlank` 两处同样反向。四处统一改 `if-eqz`：
- `getStravaCookie`：prefs 取到非空即返回，空/无则回落静态副本；
- `isStravaWebLoggedIn`：`null` 或空串 → false，非空 → true；
- `uploadToStravaWeb`：凭证为 null 或长度 0 才回落 prefs；`isBlank(cookie)` 为 true 才进未登录分支。

**为什么只有 Strava 中招**：登出/未登录的判定体系是全平台统一的 `isLoggedIn(DataSource)`，但每个平台各有一个自有判定函数。高驰等走 token/字段非空判定，函数本身正确；Strava 走 `isStravaWebLoggedIn()`，而该函数真值被写反，于是全 App 21 个平台里只有 Strava 恒显示「未登录」，上传也被同一函数拦下（2ms 返回「Strava 未登录，请先登录」）。

**验证**：成品包反编逐方法核对（见 `9.6.7-发布核对.md` 第 3 节 19 项 PASS）；模拟器装入后 `[fix8] cookie PRESENT -> true`、登录页「已登录平台（1）/ Strava ✓ 已登录」；诊断桩已全部清除（全树 `[fix8]` 计数 0，构造期自测写入已删除，`PrefsManager.<init>` 恢复官方原版）。

# 鸡翅幸哲迈进OB iOS 版（开发体验版）

> 待真机验证：整个工程是全新 Swift 原生重写，目前只是骨架，
> 各平台的登录、下载、上传逻辑还没接完，真机上能跑起来不代表能同步成功。
> 先在真机上把“能打开、四个 Tab 能点、登录页能显示”跑通，再一个平台一个平台验。

让运动数据自由流动 —— 21 个平台运动数据互传工具的 iOS 版。

安卓原版是 v9.6.9（包名 `com.jichi.ob.dev`），纯安卓 Kotlin，

### 网络请求（HTTPClient）

`Core/HTTPClient.swift` 是全工程唯一的网络入口，cookie 存在系统共享的地方，
登录态 App 重启后还在。2026-11-25 补了一个缺口：

- `requestRaw(...)`：返回原始响应体和状态码，非 2xx 不抛错，调用方自己判断
  （登录失败原因、403 续签、OSS 上传重试都要看状态码和错误正文）。
- 超时放宽到请求 120 秒、资源 300 秒（原来只有 30 秒，大文件上传不够用），
  单个请求还能自己传 timeout 收紧或放宽。
- PUT 可以不带 Content-Type：body 为 nil 时不设，OSS 签名 PUT 要求不带，带了会 403；
  第一次不带、403/400 再带上重试的逻辑在 iGPSPORT 那边原样保留。
- 各平台原来直接用 `URLSession.shared` 的状态敏感调用，已统一迁到 `requestRaw`；
  只有 Wahoo SAML、Zepp 登录那种“不跟随重定向、要读 302 Location”的，
  还用各自的自定义 session，那是 HTTPClient 没有的能力，迁不动，现状如此。

## 凭证占位说明

App 里有些平台要开发者自己的凭证才能登录，仓库里**绝不放真实值**，
代码里全是空字符串占位，用户在 App 的关于页自己填，填完只存本机钥匙串。

### CI 打包注入（Secrets，不进仓库、不进日志）

CI 编译前会用 GitHub Secrets 的值重写编译机上的 `Core/BuiltinSecrets.swift` 再编译，
打出来的未签名 .ipa 里就带真实值、开箱即用；推上去的代码本身还是占位、干净的。
在仓库 Settings → Secrets and variables → Actions 里配这 9 个（只写名，不写值）：

| Secret 名 | 用在哪 | 没配会怎么样 |
|---|---|---|
| WAHOO_CLIENT_ID / WAHOO_CLIENT_SECRET | Wahoo 登录 | Wahoo 登不上，其他 20 个平台不受影响 |
| GARMIN_CONSUMER_KEY / GARMIN_CONSUMER_SECRET | 佳明 OAuth1（预留，链路待补实现，配了暂时也不生效） | 佳明 OAuth1 链路暂不可用 |
| SUUNTO_CLIENT_ID / SUUNTO_CLIENT_SECRET / SUUNTO_SUBSCRIPTION_KEY | 松拓 OAuth2 授权 | 松拓登不上 |
| BRYTON_MOBILE_API_KEY | 百锐腾下载 | 百锐腾拉不到数据 |
| TRIAL_LICENSE_SALT | 体验码门禁盐值 | 体验码校验不通过 |

没配的 Secret 在编译机上留空/占位，App 照常能编、能打开。CI 日志里只打印注入了几项的名字，不打印值。
本地自己编的话不用配 Secrets，直接在 App 关于页填，填完只存本机钥匙串。

| 凭证 | 用在哪 | 没填会怎么样 |
|------|--------|-------------|
| Wahoo Client ID / Secret | Wahoo 登录 | Wahoo 登不上，其他 20 个平台不受影响 |
| 佳明 Consumer Key / Secret | 佳明国内/国际登录 | 佳明登不上 |
| 松拓 Client ID / Secret / Subscription Key | 松拓 OAuth2 授权 | 松拓登不上 |
| 百锐腾 Mobile API Key | 百锐腾下载 | 百锐腾拉不到数据 |
| 体验码门禁盐值 | 发体验码校验用 | 体验码校验不通过（见下一节） |

填入口在关于页，`AppConfig` 单例（`Core/Storage.swift`）负责存取，
关于页那组负责把输入框接上。

## 体验码门禁（已保留）

安卓版的体验码系统在 iOS 版里**原样保留**，逻辑照安卓 `util/TrialLicense.kt`，
实现放在 `Services/TrialLicense.swift`（体验码组负责写）。

大白话讲，就是一串“口令”制度：

- **怎么发码**：每个手机有一个设备 ID，
  从 2026-09-01 起，每 14 天算一个周期，编号 P001、P002、P003……往后排。
  体验码长这样：`P008-ABC123`（周期码，当期有效）或者 `LIFE-ABC123`（永久码）。
  横杠后面那 6 位是校验码，算式是 MD5(设备 ID + 周期号/LIFE + 盐值）取前 6 位、转大写。
  盐值是发码的“底料”，不知道盐值算不出正确的校验码。
- **盐值**：代码里一律是占位符 `GATE_SALT_PLACEHOLDER`，
  绝不写真实盐值。用户在关于页自己填真实盐值后才能发码；
  占位盐值下校验不会通过，这是正常的，不是 bug。

### 在哪验码（关键，别写反）

只在原来那几个功能入口验码，有码能用、没码不能用：

1. 新建任务
2. 轨迹合并
3. 一对多同步开始前（一个来源往多个目标传的时候）
4. 一对多任务运行前

一对一同步（一个来源往一个目标传）**不验码**，直接能用。

App 本身能点进去、原来的界面不动。**不要做成 App 级开屏门禁**——
之前安卓 v9.6.9 那种一打开就拦住、改标题、藏掉“暂不使用”按钮、
不让返回、关了就退 App 的做法是做过头了，不符合用户的意思，iOS 版不许这么干。

### 弹窗长什么样

验码弹窗上有“暂不使用”按钮，点它只关掉弹窗，对应那个功能打不开，
App 不退出，用户还能继续用别的、不用验码的功能。
